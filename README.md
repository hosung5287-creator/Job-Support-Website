# 취업 상황판 (Job Dashboard)

채용 공고를 내 이력서 기준으로 평가해 점수와 등급을 매기고, 지원 현황을 한 화면에서 관리하는 개인용 웹 대시보드입니다. 공고마다 버튼 한 번으로 **심층 조사 보고서**와 **자기소개서 초안(PDF)** 을 만들 수 있습니다.

데이터베이스 없이 JSON 파일을 데이터 소스로 쓰고, 모든 작업은 내 컴퓨터에서만 실행됩니다.

## 주요 기능

### 1. 공고 목록과 요약
- **상단 요약**: 총 공고 수, 등급별(A/B/C/D) 개수, 평균 점수
- **카드 / 테이블 보기** 전환
- 항목별 표시: 회사, 직무, 등급 뱃지, 점수, 매칭 이유(상세보기로 펼침), 부족 키워드, 원본 공고 링크
- **상세보기**: 근무지·마감·경력·학력·고용 형태·급여와 항목별 점수(직무 적합도, 기술 스택, 경력, 근무 조건, 성장성)
- **정렬**: 점수순 / 회사순 / 최신순
- **필터와 검색**: 등급(복수 선택), 회사·직무·이유·키워드 검색

### 2. 지원 상태 관리
- 공고마다 `미지원 / 지원함 / 서류통과 / 탈락` 드롭다운
- 변경하면 `data/status.json`에 저장하고 브라우저 localStorage에도 백업
- 파일 저장에 실패하면 브라우저 백업을 쓰고, 다음에 열 때 파일로 다시 저장

### 3. 마감 임박 표시
점수 오른쪽에 남은 기간을 뱃지로 표시합니다. 색과 글자(`D-n`)를 함께 써서 색에만 의존하지 않습니다.

| 남은 기간 | 표시 |
|---|---|
| 10일 이상 | 초록 |
| 6~9일 | 회색 (남은 일수만) |
| 5일 이하 | 노랑 |
| 2일 이하 | 빨강 (당일은 "오늘 마감") |
| 마감 지남 | 회색 "마감" |
| 상시채용 | 회색 "상시" |

### 4. 심층 조사
공고 카드의 **심층 조사** 버튼을 누르면 공고 본문과 회사를 조사해 보고서를 만듭니다.
- 공고 분석(실제 업무, 필수·우대, 숨은 요구, 회사에 물어볼 질문)
- 회사 분석(사업·기술 스택, 최근 동향, 개발 문화, 예상 과제, 경쟁사)
- 내 이력서와의 매칭표, **이력서 수정 인사이트**, 자소서·면접 포인트, 지원 전 체크리스트
- 결과는 `data/deep-research/{공고번호}.md`에 저장되고 화면에서 바로 읽을 수 있습니다.

### 5. 자기소개서 초안 (초안 → 검토 → PDF)
**자소서 초안** 버튼 한 번으로 3단계가 순서대로 실행됩니다.
1. **초안 작성**: 이력서, 면접 스토리, 공고 원문, 심층 조사 보고서, 작성 기준(`cover-letter.guide.md`)을 읽고 4개 항목(성격의 장단점, 지원동기, 직무역량 및 문제해결, 성격 및 소통)을 씁니다.
2. **검토**: 두 번째 작업자가 문장마다 근거를 확인하고 근거 없는 사실·숫자를 고칩니다. 인사담당자 시선 평가, 예상 면접 질문 10개, 공고의 AI 활용 안내 확인을 붙입니다.
3. **자동 점검과 PDF**: 항목별 글자 수, 상투어, 근거 자료에 없는 숫자는 모델이 아니라 코드로 점검합니다. 결과는 PDF로 출력합니다(본문과 검토 결과는 쪽이 나뉩니다).

작성 원칙은 "후보자가 실제로 한 일만 쓴다"입니다. 근거가 없는 내용은 지어내지 않고 **제출 전 확인** 질문으로 남깁니다.

### 6. 공고 점수화 스크립트
`data/rank-saramin.mjs`가 수집한 공고에 가중치를 적용해 `ranked-jobs.json`을 만듭니다.

| 항목 | 가중치 |
|---|---|
| 직무 적합도 | ×3 |
| 기술 스택 일치 (공고 키워드와 이력서 대조, 스크립트가 계산) | ×2 |
| 경력연차 부합 | ×1 |
| 근무 조건 | ×1 |
| 성장성 | ×1 |

각 항목은 0~5점이고 합계를 100점으로 환산합니다. 등급은 A 80점 이상, B 65점 이상, C 50점 이상, D 그 미만입니다.

### 7. 공고 새로 고침
상단 오른쪽 **공고 새로 고침** 버튼("공고" 링크 왼쪽)을 누르면 목록을 최신 상태로 맞춥니다.
1. **수집**: 처음과 같은 사람인 검색 조건 3개로 검색 결과를 가져옵니다.
2. **마감·상시 공고만 다시 확인**: 마감일이 지난 공고는 마감 처리합니다. 상시 공고는 검색 결과에 없으면 공고 페이지의 마감일 정보를 읽어 판단하고, 판단이 안 되면 그대로 둡니다. 마감일이 남은 공고는 건드리지 않습니다.
3. **신규 공고 평가**: 처음 보는 공고를 Claude 작업자(읽기 전용)가 기존과 같은 기준으로 평가합니다. 한 번에 최대 20건이며, 나머지는 다음 새로 고침 때 평가합니다.
4. **순위 다시 계산**: 점수화 스크립트로 `ranked-jobs.json`을 다시 만들고 목록을 갱신합니다.

기존 공고의 점수는 바꾸지 않고, 쓰기 전에 `saramin-jobs.json.bak`으로 백업합니다. 마감된 공고는 지원 상태가 "미지원"이면 목록에서 숨기고, 지원 기록이 있으면 계속 보여 줍니다.

## 기술 스택
- Next.js 16 (App Router), React 19, TypeScript
- `react-markdown` + `remark-gfm` (보고서 렌더링)
- 데이터: JSON 파일 (DB 없음)
- 심층 조사·자소서 생성: [Claude Code](https://claude.com/claude-code) CLI를 읽기 전용 도구 범위로 호출
- PDF: 설치된 Edge 또는 Chrome의 헤드리스 인쇄

## 시작하기

### 필요한 것
- Node.js 20.9 이상
- 심층 조사·자소서 버튼을 쓰려면 로그인된 `claude` 명령어 (목록, 필터, 지원 상태만 쓸 때는 필요 없음)
- 자소서 PDF를 만들려면 Edge 또는 Chrome (다른 브라우저는 `PDF_BROWSER`에 실행 파일 경로 지정)

### 실행
```bash
cd job-dashboard
npm install
npm run dev
```

http://localhost:3210 을 엽니다. 동작 점검은 서버가 켜진 상태에서 `npm run check`입니다.

## 폴더 구조와 필요한 파일
이 저장소에는 **앱 코드만** 있습니다. 이력서, 자소서, 공고 평가 같은 개인 자료는 `.gitignore`로 제외되어 있어서 직접 만들어야 합니다. 앱은 `job-dashboard`의 **상위 폴더**를 작업 루트로 씁니다.

```
my-job-search/
├─ job-dashboard/          이 저장소의 앱
├─ data/
│  ├─ ranked-jobs.json     공고 순위 (화면이 읽는 데이터)
│  ├─ status.json          지원 상태 (앱이 자동 생성)
│  ├─ deep-research/       심층 조사 보고서 (자동 생성)
│  └─ rank-saramin.mjs     점수화 스크립트
├─ cv.md                   내 이력서 (마크다운)
├─ config/profile.yml      프로필
├─ interview-prep/story-bank.md   면접 스토리 (자소서 재료)
├─ modes/                  조사·글쓰기 규칙 파일
└─ output/cover-letters/   자소서 초안과 PDF (자동 생성)
```

### `ranked-jobs.json` 형식
```json
[
  {
    "rank": 1,
    "company": "회사명",
    "title": "공고 제목",
    "url": "https://www.saramin.co.kr/zf_user/jobs/relay/view?rec_idx=12345678",
    "score": 88.8,
    "grade": "A",
    "reason": "매칭 이유 한 줄",
    "missing_keywords": ["Git"],
    "breakdown": { "job_fit": 5, "tech_stack": 4.5, "experience": 5, "conditions": 3, "growth": 3.5 },
    "location": "경기 과천시",
    "deadline": "~ 11/30(월)",
    "career": "신입",
    "education": "초대졸↑",
    "employment": "정규직",
    "salary": "면접 후 결정"
  }
]
```
`url`의 `rec_idx` 숫자는 사람인 공고 번호이며, 최신순 정렬과 심층 조사·자소서 주소에 쓰입니다. 필수 필드는 `company`, `title`, `url`, `score`, `grade`, `reason`, `missing_keywords`입니다.

### 환경 변수
| 이름 | 용도 |
|---|---|
| `JOBS_DATA_DIR` | 공고·상태 JSON 폴더 (기본값: 상위 폴더의 `data/`) |
| `CAREER_OPS_ROOT` | 작업 루트 (기본값: `job-dashboard`의 상위 폴더) |
| `PDF_BROWSER` | PDF를 만들 브라우저 실행 파일 경로 |

## 설계 메모
- 심층 조사·자소서 작업자는 **읽기 전용 도구 범위**로 실행됩니다. 파일 쓰기, 명령 실행, 하위 에이전트는 막고, 결과 파일은 앱이 직접 저장합니다.
- 작업 시작 요청(POST)은 다른 사이트에서 온 요청이면 거부합니다. 작업 한 번이 Claude 사용량을 쓰기 때문입니다.
- 진행 상태는 서버 메모리에만 있어서, 서버를 재시작하면 진행 중이던 작업은 잊히고 다시 눌러야 합니다.
- 작업 시간은 심층 조사 몇 분, 자소서 초안 약 10~15분, 공고 새로 고침(신규 평가 포함) 몇 분입니다.
- 개인 용도로 만든 도구라 로그인이나 사용자 구분이 없습니다. 인터넷에 공개해서 쓰지 마세요.

## 참고
- 공고 평가와 모드 구성은 오픈소스 [career-ops](https://github.com/career-ops-hq/career-ops)의 개념(공고 평가, 심층 조사, 데이터와 사용자 파일 분리)을 참고했습니다.
- 화면 디자인은 Apple 웹사이트의 디자인 분석 문서의 원칙(단일 강조색, 17px 본문, 알약형 버튼)을 따랐습니다. 마감 뱃지의 신호색만 예외입니다.
